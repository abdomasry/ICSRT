# ICSRT Website Design Rollout Plan

## Approved direction

The home page establishes the direction for the public website:

- Cinematic, full-width imagery with a dark overlay.
- Charcoal surfaces, warm sand highlights, and off-white type.
- Large, condensed, uppercase headings with direct calls to action.
- Sharp edges, fine dividers, and structured grid layouts.
- Font Awesome icons used only where they clarify a service or action.
- Original ICSRT imagery and content; no third-party branding or copied assets.

## Shared foundation

Before changing individual pages, create a small shared visual layer for the public site:

1. Define reusable colors, type scale, spacing, buttons, section headers, cards, and form controls.
2. Refresh the navigation and footer to match the black-and-sand palette.
3. Add a reusable image-hero component with accessible text contrast and mobile crop controls.
4. Apply the same keyboard focus, reduced-motion, responsive, and Arabic RTL behavior already used on the home page.

## Page rollout order

### 1. High-traffic public pages

| Page | Design treatment |
| --- | --- |
| Services | Product-range grid with large service imagery, concise specifications, and clear request buttons. |
| About | Cinematic story hero, mission blocks, and a visual timeline. |
| Articles | Dark editorial index with featured article hero and structured article cards. |
| Contact | Compact, high-contrast contact form with a practical support-information panel. |
| FAQ | Clear accordion groups with restrained dividers and a contact call to action. |

### 2. Conversion and account pages

| Page | Design treatment |
| --- | --- |
| Work With Us | Recruitment-style campaign page with role/value cards and an application call to action. |
| Login, signup, password reset, email verification | Quiet utility layouts that retain the new visual tokens without distracting from the task. |
| Purchase and payments | High-clarity checkout surfaces with obvious status and payment actions. |

### 3. Member workspace

| Page | Design treatment |
| --- | --- |
| User dashboard | Dense but readable dashboard with strong status hierarchy and consistent action panels. |
| Profile, service orders, tickets | Practical tables, filters, timelines, and empty states using the same component tokens. |

### 4. Admin dashboard

| Area | Design treatment |
| --- | --- |
| Dashboard shell | Dark navigation, light work surfaces, consistent data cards, and clear table behavior. |
| Users, admins, roles | Reusable management-table and form patterns. |
| Papers, articles, services, FAQ, coupons, newsletter, social media | Reusable collection, editor, and detail-page patterns. |
| Tickets, contact requests, service orders | Queue-oriented views with clear status, priority, and response actions. |

## Delivery approach

1. Build and verify the shared public-site components.
2. Redesign the public pages one at a time, beginning with Services.
3. Review the public flow on desktop, mobile, dark mode, and Arabic RTL.
4. Apply the shared system to account pages, then the member workspace.
5. Finish with the admin dashboard, preserving its data density and workflows.

Each page is reviewed before the next group begins, so the approved home-page direction remains consistent across the website.
